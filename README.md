# GitLab Radar

GitLab Radar собирает сведения о Python-проектах в GitLab и показывает используемые технологии, зависимости и соответствие внутренним правилам компании.

## Возможности

- определение пакетных менеджеров uv, Poetry и pip; проекты без конфигурации пакетного менеджера отмечаются как неопределенные;
- поиск `pyproject.toml`, `uv.lock`, `requirements.txt` и `requirements.*.txt` в подпроектах;
- анализ прямых, опциональных и транзитивных Python-зависимостей;
- определение FastAPI и Django по прямым и опциональным зависимостям;
- анализ образов из `Dockerfile*` и Docker Compose;
- поиск, нормализация и группировка компонентов GitLab CI по registry;
- сбор настроенных project webhooks для проектов с доступом Maintainer или Owner;
- интерактивная статистика версий Python, registry и технологический радар с отдельной метрикой Python LTS;
- конструктор требований компании по пакетному менеджеру, зависимостям, инструментам, CI-компонентам, webhooks и registry;
- повторное использование результатов для неизменившихся ревизий;
- хранение снимков сканирования в SQLite.

## Требования

- Python 3.15 или новее;
- uv;
- доступ к GitLab API и проектам, которые требуется анализировать.

## Настройка

Создайте файл `.env` в корне проекта:

```dotenv
GITLAB_URL=https://gitlab.example.com
GITLAB_PRIVATE_TOKEN=<token>

RADAR_HOST=0.0.0.0
RADAR_PORT=8000
RADAR_RELOAD=false
```

`GITLAB_PRIVATE_TOKEN` должен принадлежать пользователю с доступом к анализируемым проектам.

## Запуск

Установите зависимости:

```shell
uv sync
```

Запустите приложение:

```shell
uv run gitlab-radar
```

После запуска откройте `http://0.0.0.0:8000` и запустите сканирование в разделе «Управление».

В разделе «Требования» слева показываются группы, а справа — описание и правила выбранной группы. Группы и правила внутри них сортируются перетаскиванием, а создание и редактирование выполняются в отдельных окнах. В группе может быть не больше шести требований; перенос выполняется отдельной командой у правила. Исходный набор загружается из fixtures в `src/gitlab_radar/fixtures`; дальнейшие изменения хранятся в SQLite.

## Особенности

Сканирование получает только целевые конфигурационные файлы, а анализ выполняется локально. Для неизменившейся ревизии проект использует предыдущий результат. Данные и загруженные файлы сохраняются в каталоге `data`.

Зависимости в каталоге учитываются относительно проекта: одна библиотека может быть прямой в одном проекте и транзитивной в другом. Docker-образы и компоненты GitLab CI нормализуются и дедуплицируются на уровне проекта.
